## Summary

A client-only standardization and parity pass over the admin route workspace (`apps/admin`): the Administrator gets one save model with one status voice across the base editor and the Detour editor (FR-001…004), one canonical vocabulary and label style (FR-005…007), one set of panel states with an explicit "Not set" for absent values (FR-008/009), detour-stop ↔ base-stop interaction parity incl. a working `mod+s` in the Detour editor (FR-010/011), one source for every fixed semantic color so near-miss shades cannot drift (FR-012/013), no dead or confusing controls (the "Coming soon" Import stays, visibly disabled — clarification 2026-08-29), and one confirmation pattern for destructive/leave/conflict dialogs (FR-014/015). **No server, database, shared-package, or data-semantic changes** — the existing `saveAll`, draft, history, and conflict machinery are reused as-is; only their presentation and interaction surface is standardized (FR-017/018, ADR-0009/0013 unchanged). Scope per clarification: no new capabilities; an **open lane** records any capability the Administrator names at plan review in Complexity Tracking.

## Technical Context

**Language/Version**: TypeScript (strict, `@repo/typescript-config`) — React 18.3 admin SPA (Vite 5) at `apps/admin`. Client-only.

**Primary Dependencies**: Existing only — `maplibre-gl` + `react-map-gl`, `zustand` (`lib/plottingStore.ts`, `features/detours/detourStore.ts`, `lib/uiStore.ts`), `react-hotkeys-hook`, `sonner`, `@tanstack/react-query`, `@komyuter/shared`, Tailwind CSS v4 (`@theme`/CSS vars in `apps/admin/src/index.css`), base-ui/shadcn (`Label`, `SectionLabel`), `lucide-react`. **No new runtime dependencies** (research R7). New shared modules are plain TS + one shared React component each.

**Storage**: None new. localStorage drafts (`lib/draft.ts`, `komyuter.draft.{routeId}.{directionId}`, 24 h TTL) and the detour draft (`DetourGroup.tsx`) are reused untouched. No server/DB/schema changes; `data-model.md` records the client-side standardization artifacts only.

**Testing**: Vitest (`apps/admin/vitest.config.ts`, `pnpm --filter admin test`) for pure helpers: canonical label registry, semantic-color registry + a **source-audit test** (no raw `#1B6DB2`/`#0F172A`/`amber-600` duplications outside the token module — guards SC-007), panel-state helpers, detour-store reorder actions (parity with base reorder semantics, mirroring `tests/detour-store.test.ts` patterns), save-copy constants. Server tests (`pnpm --filter server test`, needs local Supabase stack) are untouched and must still pass. Reviewer walkthroughs per SC-001…SC-010 are documented in [quickstart.md](./quickstart.md).

**Target Platform**: Desktop web admin workspace (≥ 1024px per ADR-0014); mobile commuter app untouched.

**Project Type**: Web application (SPA) — a UI standardization/parity pass over the existing route-workspace surfaces; no new screens.

**Performance Goals**: No new performance-sensitive paths. Parity interactions (reorder, `mod+s`, panel states) are client-local; they must not add perceptible latency or new network requests. Save feedback duration stays at the existing 4 s "Saved just now" plate.

**Constraints**:

- **Client-only, zero contract changes**: no new server endpoints, no schema/table changes, no new `@komyuter/shared` fields, no new runtime deps (spec Assumptions; FR-019).
- **One canonical definition per semantic color and per label** (FR-005/012): every fixed semantic color and every field label is defined exactly once and consumed, never copied. `DESIGN.md` (The Route Sign, "signboard green-blue + signal amber") wins on visual values; exact OKLCH confirmed at implementation and recorded in DESIGN.md frontmatter.
- **[lng, lat]** everywhere (FR-018, ADR-0013); **no ETA** (FR-017, ADR-0009); **WCAG AA + keyboard parity** retained on every touched surface (FR-016).
- **Reuse, don't reimplement**: `saveAll` gate/conflict machinery, draft/history stacks, `SectionLabel`, `StopShape` markers, `routeColors.ts` helpers, `StatusBar` lifecycle plate all stay; only presentations unify.
- **Mod-s on the active editor** is the intended standard (clarified scope; FR-004); dialogs keep focus and intercept shortcuts (existing Esc DOM-probe pattern extended to the other hotkeys).
- Desktop-only workspace; keyboard-only operation remains first-class.

**Scale/Scope**: Single Administrator actor. Touched surfaces (audit-inventoried): `RouteList` (stops sidebar + badges), `RouteMap`, `PropertiesPanel`/`FocusPlate`/`RouteGroup`/`StopGroup`/`StopEditor`, `ConnectionSelect`, `StatusBar`, `PlotActionBar`, `NewRouteDialog`, `EmptyState`, `DetourGroup`, `DetourStopGroup`, `DetourList`/`DetourSidebar`, and the five dialogs (`LeaveConfirmDialog`, `LoadLatestDialog`, `NavConfirmDialog`, stop-delete, route-delete). A handful of new shared modules (below).

**Structure Decision**: Two new pure-logic modules in `src/lib/` (`labels.ts`, `colors.ts`) own the two registries the spec names as arbiters (FR-005/012); `map/constants.ts` re-exports color tokens to keep existing imports working — migrate raw-hex consumers to the registry in the same pass. Three new shared UI components (`SaveButton`, `PanelState`, `ConfirmDialog`) each encode exactly one of the spec's patterns (FR-001/008/015) so panels stop inventing their own. Interactions are extended where stores already own the state (reorder actions in `detourStore` mirroring base `moveStop` semantics) rather than forking or entangling the base store — the same "don't fork" rule 012 used. No changes outside `apps/admin`.
