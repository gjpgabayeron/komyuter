## Summary

The Administrator can plot a **Detour** (an "alternative route from the main route", canonical term per `docs/CONTEXT.md`) anchored to a Direction's base polyline: pick **entry** and **exit** geometry points snapped onto the base path, draw the alternative **loop** between them (reusing the road-following proxy used by the base-path editor), describe it (auto label, required commuter instruction, optional driver instruction, optional notable stops — **existing Stops only** per clarification Q1), and save atomically through the **existing** detour CRUD (`POST/PUT /api/admin/directions/:directionId/detours` / `/api/admin/detours/:detourId`). Per clarification Q2 (FR-023/SC-014), the existing server endpoints gain **minimal structural validation**: loop-start/loop-end must match entry/exit within tolerance; entry/exit-on-line and `additional_distance_meters ≥ 0` are already enforced (respectively by `assertPointOnLine` and the zod schema). The workspace additionally refuses invalid saves client-side (travel order, degenerate loop) before any request. R2 activation semantics (`active_timeframes`, `condition` — ADR-0012) are out of scope, as are new server endpoints, new tables, and new shared schema fields.

## Technical Context

**Language/Version**: TypeScript (strict, `@repo/typescript-config`) — React 18.3 admin SPA (Vite 5) + Fastify v5 API; Node ≥ 18. All validation logic lives in shared/domain modules (never duplicated UI vs server).

**Primary Dependencies**: Admin — `maplibre-gl@^5.24.0` + `react-map-gl@^8.1.2` (maplibre entry; imperative map API per spec-007 R1 correction), existing `zustand`, `react-hotkeys-hook`, `sonner`, `@komyuter/shared`. Server — Fastify v5 + drizzle-orm (existing). **No new runtime dependencies** (see research R5).

**Storage**: PostgreSQL/PostGIS via the **existing** `detours` table (`apps/server/src/db/schema.ts:170-191`) and `notable_stops` JSONB — **no schema changes**. Client-local drafts in `localStorage` (extended namespace `komyuter.draft.{routeId}.{directionId}.detours`, 24h TTL, never sent to the server).

**Testing**: Vitest — admin unit tests (node env, pure helpers only: `lib/coords.ts` projection/length, detour planning store, draft, selection); server unit (loop-endpoint validation, tolerance math) + integration (`specs/001-…` TDD suite, needs local Supabase stack + `apps/server/.env`). Server tests written FIRST (red) per `specs/001-local-supabase-backend/tasks.md`.

**Target Platform**: Desktop web (admin workspace, ≥ 1024px per ADR-0014). Mobile commuter app untouched.

**Project Type**: Web application — React SPA (admin dashboard) + Fastify API + PostGIS; feature is one editor surface within the existing routes workspace.

**Performance Goals**: Snap-parity with the base-path editor (debounce ~300 ms client-side, research R2); loop waypoint requests re-use the server proxy's 25-waypoint chunking; additional-distance computation exact (haversine sum, no rounding-into-plausibility).

**Constraints**:

- `[lng, lat]` everywhere; no conversion layer (ADR-0013).
- **No new server endpoints** (FR-023 qualifies existing ones); no schema/table changes; no new shared-package fields.
- Exact distances only; no ETA anywhere (ADR-0009).
- Server tolerances: `DETOUR_ON_LINE_TOLERANCE_METERS = 30` (existing, entry/exit on base polyline); new loop-endpoint tolerance = same 30 m constant.
- Notable stops reference **existing** Stops only (clarification Q1); no stop creation in the Detour editor.
- Distinct visual style for detour loops (spec FR-012); exact color/dash treatment decided at implementation, signal amber reserved.
- Reuse workspace safety behaviors (drafts, Undo/Redo, styled confirms, toasts, conflict plate, keyboard/WCAG AA) — not re-designed (ADR-0014).

**Scale/Scope**: Single Administrator actor; one Direction open at a time in the workspace; a handful of Detours per Direction (list stays ordered/scannable); two editing modes (new Detour from the floating bar; edit/remove from the nested list).

**Structure Decision**: Keep the Detour feature as a sibling feature folder `features/detours/` beside `features/routes/`, because the base-path editor lives there and its store (`plottingStore.ts`), map layers, snap binding, and save APIs are additive building blocks. Reuse, don't fork: entry/exit/loop share `snapPreview` + `lineLayerSpec`; the planning store is a NEW zustand slice rather than entangling the base path store (different draft namespace, different history entries, different save target). Server work is deliberately minimal — two additions inside existing handlers + one canonical validator in `domain/validation.ts`, matching the repo's "server owns domain invariants" convention. No new endpoints, no new tables, no new shared fields — the workspace and server consume the exact `@komyuter/shared` detour contracts that already exist.
