# DEVIATIONS — Thesis ↔ Codebase Reconciliation

> **Purpose.** This document records every instance where the **current codebase** (its implementation _and_ its authoritative design docs / ADRs) contradicts the **thesis paper** (`docs/thesis/CHAPTER1.md`–`CHAPTER3.md`). It is the reconciliation map we resolve **before** continuing the admin dashboard.
>
> **Source of truth rule.** The thesis paper is the source of truth, but it is **amendable where the code's argument is valid**. Each deviation below carries a verdict and the specific amendment to make in the thesis, so nothing is left as an un-decided conflict.
>
> **Status legend.**
>
> - **Amend thesis** — the codebase's position is valid and defensible; the thesis text must change.
> - **Planned / not implemented** — the thesis describes a feature that is not yet built; not a contradiction, but tracked so the reconciliation map stays complete.
> - **Doc-only (deferred)** — the conflict is inside the codebase's own docs, not the thesis; fix in a later docs pass.
> - **Appendix (codebase-internal)** — drift within the codebase that is unrelated to the thesis but worth recording.

---

## 0: How the codebase currently stands (verified)

- `apps/server` is an **admin CRUD API only** (`src/api/index.ts` registers `status, auth-login, auth, routes, fare-configs, directions, stops, detours, restrictions, export, mapbox`). **No graph builder, no Dijkstra, no navigation endpoint exists.**
- `apps/mobile` is an **untouched Expo starter template** (no AR, no map, no GPS-trace, no trust scoring; `react-native-reanimated@4.3.1` is present but unused).
- `packages/shared` is **types + Zod schemas only** — no `fareCalculator`, no preference-profile weights.
- Therefore the **authoritative "current implementation spec" for the routing/AR/trust layers is the design docs + ADRs** (`docs/BACKEND.md`, `AGENTS.md`, `docs/adr/*`), and it is there that the contradictions with the thesis live. This is explicit throughout the document.
